## 1. move_destination_mismatch（sasae_location.rs `check_timeline_with_table`）
### 条件（コード上）
1. 場面 j が**鎖の中**: `relative_order == continuous`（または最初の注釈場面が unknown）で、時間の evidence が ambiguous でない（行 759）。鎖の外の場面は検査も状態更新もしない。
2. 場面 j の `location_id` がある（行 810）。
3. 人物 c が場面 j の `present_character_ids` に居る（行 772）。
4. c の「直近の所在」`state[c]` が存在し、間に注釈の無い場面が無い（行 814〜821）。
5. `state[c].loc` と `location_id` が別の場所（`same_place` で表記ゆれを吸収、行 822）。
6. 場面 j に、c が `location_id` へ向かう `MOVED_TO` が**無い**（あれば「説明済み」、行 826）。c の別の場所への `MOVED_TO` がある場合もスキップ（行 831）。
7. 台帳の場所階層の「微移動」ではない（既定では台帳なし）。
8. **`state[c].from_move == true`**（直近の所在が「MOVED_TO の行き先」由来であること。行 852）。同席（場面の場所）由来の所在変化は「連続場面の通常の移動」として count-only（`place_changes`）にして**指摘しない**。
9. 時間経過（`elapsed_hint`）を挟んだ場合は `time_gap` で「要確認」の count-only（行 844）。

つまりこの規則は「人物が**行き先を明示して出発**した（MOVED_TO）のに、次に同席した場面の場所がその行き先と違う」ときだけ指摘する。単に場面ごとの場所が変わるだけでは指摘しない。

### H2 の場面 5（山へ向かった厨子王が浜にいる）が落ちた条件
- 注釈（H2final、場面番号は 0 始まり）: 場面 4 は `location_id=由良が嶽の裾`、厨子王の `MOVED_TO 由良が嶽の裾`、場面 5 は `location_id=浜の汐汲み場`、同席に厨子王を含む（`present=[zushio, kikori, anju, kohagi]`）。厨子王の `MOVED_TO` は場面 5 に無い（安寿の `MOVED_TO 潮を汲む場所` のみ）。
- 場面 4 の `MOVED_TO` の行き先（由良が嶽の裾）は場面 4 の所在と同じなので、**到着済みとして持ち越されない**（行 883〜887）。場面 4 の終わりの `state[zushio]` は「同席由来」（`from_move=false`）の由良が嶽の裾。
- 場面 5: 条件 1〜7 を満たすが、**条件 8 で落ちる**（`from_move == false` のため `place_changes += 1`、行 852〜856）。
- 診断出力の裏付け: `s2_location_change_count`（count-only の所在変化）が基準版 11 に対し挿入版 12 に増え、`s2_move_destination_mismatch_count` は 0。挿入による所在変化は count-only に入っている。
- 結論: **注釈は食い違いを記録していた（場所が変わった）が、規則の定義上は「指摘」ではなく「通常の移動」の件数になる**。この規則の定義（行き先を明示した移動の不履行）を、挿入文が満たしていなかった。「山路をさして行く」文と山での場面は同じ場面 4 に入っており（挿入版の場面 4 は朝の出発から山での涙まで）、厨子王の `MOVED_TO 由良が嶽の裾` はその場面 4 の所在と一致するため、次の場面への「未到達の移動」にならなかった。
- 基準版で出ていた 1 件（場面 3）との関係: 基準版の注釈では未到着の `MOVED_TO` が持ち越され、次の場面の場所と食い違った（`from_move=true`）。挿入版では同じ箇所の注釈が違った（注釈の揺れ。I3 で確認）。

### 変えるなら（実装はしない）
- 指摘にするのは規則の定義（行き先明示の不履行）に忠実な現状のとおりで、バグではない。「同席由来の所在が、明示なしに別の場所へ変わる」を指摘にするには、行 852〜857 の分岐（`place_changes` に回している箇所）を指摘へ変える必要がある。その場合、通常の場面転換がすべて指摘になるため、誤爆が大幅に増えると見込まれる（`s2_location_change_count` が 11〜12 件ある作品で、それがそのまま指摘候補になる。見込みであり測っていない）。凍結中の物差しに触れる変更で、承認が要る。

## 2. place_conflict（sasae_stage2.rs `check_place_with_table`）
### 条件
1. **隣り合う 2 場面**（場面 j と j-1）を比べる（`prev` は直前の場面のみ）。
2. 時間が重なる: 場面 j の `relative_order == parallel`、**または** 2 場面の `explicit_time` が**同一の文字列**（`x == y`、行 418。`ambiguous` の扱いなどの条件は別）。
3. 両場面に `location_id` があり、別の場所（`same_place` を除く）。
4. 両場面の `present_character_ids` の**両方に居る人物**ごとに 1 件（同一原因が人物数ぶん出る。第1弾 B の重複の原因）。
- 比べるのは**場面の `location_id`（場面あたり 1 つの所在）**。場面の中の 1 文の記述は、注釈が `location_id` を変えない限り影響しない。

### H2 での位置づけ
- 挿入した 2 文は同じ場面（場面 6）に入り、跨ぎ場面になっていない。さらに場面 6 と場面 7 の `explicit_time` は `十日目の夕暮れ` と `ある日の暮れ` で別の文字列、`location_id` は両方 `小屋`。**条件 2・3 のどちらも満たさない**（注釈データ）。→ 検証として不成立だった第2弾の判断を、コードの条件で裏付けた。

## 3. pov_contamination（diagnose_slice.rs `sasae_lens_ext`、`sasae-core` の FID 判定）
### 条件（コード上、行 503〜514）
1. 場面の注釈に **`scene_meta.pov_character` がある**（`pov` が `None` なら検査しない、行 504 の `Some(p)`）。
2. 本文の 1 文（地の文、かぎ括弧の中身を除く）が **FID（自由間接話法）と判定**される（`s.fid.is_fid`）。判定は**注釈ではなく本文**から（`sasae-core/src/fid.rs`）: 5 つのトリガー T1〜T5 の重みの和が 0.50 以上。T1（0.30）: 過去形の流れの中の非過去・体言止め、T2（0.25）: 近称の指示語などの発話時ダイクシス、T3（0.35）: 三人称の主観形容詞の裸の使用、T4（0.35）: 認識モダリティ・疑問・詠嘆・言いさしの文末、T5（0.25）: 直前 1〜2 文の知覚・認知動詞。
3. その FID の**帰属先**（`attributed_to`）が、場面の `pov_character` と別の人物。帰属先は、直前の知覚動詞の主語（`focal`）、なければ場面の pov、なければ談話の中心（行 1309〜1321）。
4. すべて満たすと、その文を `pov_contamination`（根拠: attributed_to、pov）とする。

### H2 の挿入（奴頭の内面、樵の内面）が落ちた条件
- 奴頭（挿入版 場面 3）: 場面 3 の `pov_character` は **null**（注釈）。→ **条件 1 で落ちる**（その場面の pov 検査自体が行われない）。`pov_character` が入っていた場面は 4 と 5（厨子王）だけ。
- 樵（場面 5）: 場面 5 の `pov_character = zushio`（注釈）。挿入文「樵は、亡くなった自分の子をこの童に重ねて、胸が痛んで仕方がなかった。」は、明示された主語（樵）を持つ過去形の叙述で、文末は「た」。→ **条件 2 で落ちると推測**: T1（非過去・体言止めが条件）と T4（認識モダリティ・疑問・詠嘆・言いさし）は文末の形から発火しにくく、T3（裸の主観形容詞）の語も無い。残る T2（近称指示語、「この童」がこれに当たるかは未確認）と T5（直前文の知覚動詞）の和は最大 0.50 で、両方が発火したときだけ閾値に届く。実際に発火したかは、診断出力に文ごとのスコアが無いため**未確認**。出力としては `fid_pov_contamination_count=0`（挿入版）、`fid_sentence_count` は挿入版 15・基準版 13（挿入が FID と判定された文を増やした可能性はあるが、どの文かは未確認）。
- 注釈側の事実: 注釈者は、樵と奴頭の内面を `STATE_CHANGED [emotion]` の事実として記録していた。**この事実は pov_contamination の判定に使われない**（判定は本文の FID と `pov_character` だけ。注釈の `STATE_CHANGED` は自由文で、機械照合されない）。
- 結論: pov_contamination は「**場面の pov が注釈にある場面で、本文が自由間接話法の形（文末の形・指示語・知覚動詞など）をとり、その帰属先が pov と別の人物**」という狭い現象を拾う規則で、「明示された主語による他人物の内面の叙述」（挿入文の型）は定義の外。第1弾で S1 の pov 12 件が全て not_real だった理由（一人称の語りを他人物の内面と読んだ等）とも整合する: FID の判定が本文の形に基づくため、一人称の語りや推測の文末で発火しやすい一方、三人称の明示的な内面描写は拾わない。

### 変えるなら（実装はしない）
- 挿入文の型（明示主語の内面叙述）を拾うには、本文の「感情・思考の述語に他人物が主語」という別の検査が要る。既存の FID 判定の閾値や重みの変更ではなく、新しい規則になる（凍結中の物差しの外だが、規則の判定ロジックの追加で承認が要る）。pov を null の場面にも適用する案は、pov の無い場面で帰属先を決められないため、定義が変わる。
- 現状の規則は、第1弾の 12 件の誤爆を出す一方、挿入した型は拾わない。表示を候補扱いにした第2弾 H1 の対応は、この性質と矛盾しない。

## 4. 追加で分かったこと（I2 の設計への入力）
- place_conflict を検出させるには、注釈の `explicit_time` を**隣り合う 2 場面で同じ文字列**にし、`location_id` を**別**にする必要がある（または 2 場面目が `parallel`）。注釈者の書き方に依存するため、検出の有無は注釈の揺れの影響を受ける。
