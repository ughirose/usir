# Phase 26.1: Tier-M フォージの分位点 3 モード割当 (2026-11-06)

## 実装
- `python/usir_py/usir_forge.py`: `assign_modes_quantile(Z, dialogue)`。作家 1 人分の全窓に対し、Mode 1 (Dialogue) = 会話シグナル上位 25%、残りのうち Mode 2 (Climax) = `z(g_shock) + z(||p||)` 上位 25%、残り = Mode 0 (Narrative)。z は作家コーパス内(母標準偏差)、同点は index の小さい方を優先。窓数 < 20 は `None`(呼び出し側が "rule" に戻る)。
- `python/usir_py/style_atlas.py`: `distill_genome(..., mode_assign="rule"|"quantile", dialogue=...)`、`build_atlas(..., mode_assign=...)`、`quote_ratios(text)`。既定は "rule"(従来と同一バイト列、テストで確認)。重みは割当後の経験割合、重心・共分散は既存のシュリンケージ(scaled α=0.75 / legacy)で各モードの割当窓から計算。
- 会話シグナル: 窓内の括弧文字(「」『』)の割合。`classify_mode_24d` 自体は会話の引用シグナルを持たない(`add_chunk` のみ文単位で「 / 『 の有無を見る)ため、`add_chunk` と同じ種類の記号を窓単位の比率にした。窓に会話が無い作家(窓の多くで比率 0)では同点が多く、その場合の上位 25% は index 順で決まる。
- TS: `packages/usir-core/src/schema/usirForge.ts` に `assignModesQuantile` を移植(Tier-M コンパイラ自体は TS に既存だが、作家コーパス単位の蒸留経路は Python のみ)。パリティ fixture `packages/usir-core/tests/fixtures/quantile_modes_parity.json`(Python 生成、20/57/200 窓、同点あり)と `tests/quantile-modes-parity.test.ts`。
- `scripts/build_aozora_style_atlas.py --mode-assign quantile`: `artifacts/style_atlas/quantile/<author>.usir`(+ `legacy/`)と `quantile/atlas.json` を出力。既存ファイルは変更していない。

## 限界・未検証
- 会話シグナルは括弧文字の比率のみ。括弧を使わない会話体(文語)や、括弧の多い非会話(引用・題名)は区別できない。
- 3 モードの割合は構成上ほぼ固定(56/25/19%)。「その作家が実際に会話/クライマックスをどれだけ含むか」は反映されない。作家内クラスタリング(k-means 等)は未実施。
- LOWO は単一分割・n=46。窓は 50% 重なるため窓単位の独立性なし。quantile の分位点は LOWO では「当該作品を除いたコーパス」で再計算している。
- 割当は作家コーパス単位であり、`add_chunk` 等のストリーミング経路(1 サンプルずつ)には適用できない。遷移行列は割当モード列の隣接窓(作品境界でリセット)から計算。
- TS 側は割当関数のみ移植。TS の `OSWEStreamingCompiler` に `mode_assign` オプションは追加していない。
