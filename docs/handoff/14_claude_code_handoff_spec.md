## 1. これまでの達成事実と現在地（Fact Sheet）

直近の複数ラウンド検証（コミット `5c07ef5` → `8786b06` → `3f288f0` → `5158471` → `f8b30d6` → `38219ba` → `73c8ce8` → `d546da5`）を経て、以下の構造的課題が解明・実証されました。

### ① 解消・実証された事項
1. **Colab 接続窓の誤認解体**:
   - 当初「160秒の固定窓で切断される」と誤認していたが、原因は長時間の無言ストリームによるクライアント側ソケット・アイドル切断であった。
   - `colab_execute` の `timeout: 600`（10分）指定と、節・段落ごとの `sys.stdout.flush()`（定期 heartbeat）により、240秒以上の重厚な深層学習推論ループが安定完走するようになった。
2. **長尺生成の文字数達成**:
   - `max_clauses_per_paragraph = 8` の人為的クランプを撤廃し、20節到達前の EOS ロジットペナルティ（$-10.0$）を導入したことで、総文字数 **2,000〜2,350字**（段落あたり20〜25節）を達成。文末の「、」途切れもゼロ件（28節以降の文末終止ロジット誘導＋置換補正）となった。
3. **提案分布（Proposal）への運動量注入による Climax 本文分岐の実証**:
   - 事後リサンプリング（SMC重み付け）のみでは、平坦な4候補の中から Greedy Top-1 が選ばれ続け、本文が一字一句同一になる病理が存在した。
   - 候補数を $N=8$ に拡張し、放出運動量ノルム $\|\mathbf{p}_{\text{discharge}}\|$ に連動させた温度スプレッド（0.7〜1.3）および読点・句点ロジットバイアスを注入したことで、seed 3, 42, 137 の全条件において **Climax 段落の本文が類似度 0.09〜0.22（別文）へ明確に分岐** した。1% 摂動対照実験により、この分岐が単なるノイズではなく放出運動量ノルムの差異から生じていることが確認された。
4. **文字コードレベルの言語境界保証**:
   - 文字列ブラックリストによるモグラ叩きを撤廃し、漢字の JIS X 0208（`strict` な `shift_jis` 符号化検証）を導入。簡体字（「变」「这」等）や中国語句読点は機械的に除外され、ラテン語・JIS外漢字混入はゼロ件となった。

## 2. 新セッションで直ちに取り組むべき残存課題（Pending Issues）

現在の課題は「力学が動くか」の段階を抜け、「生成された長尺散文の文学的・日本語的品質」および「モデルスケーリング」のフェーズに移行しています。

### 課題A: アシスタント口調・メタ文の侵入（最優先）
- **現象**:
  - seed 137 の制約なし段落5に「…（残りは省略）」という AI 要約文が出現。
  - seed 137 の制約あり段落1に「過ごしてあげましょう」「大切ですね」等のアシスタント会話口調が混入。
- **根本原因**:
  - Qwen2.5-Instruct のチャットチューニング（RLHF）の基底アライメントが、長尺散文生成の途中でプロンプトのコンテキスト境界を誤認し、「ユーザーへの応答・アドバイス」にモードスリップしている。
- **解決方針**:
  - 小手先の禁止ワード辞書ではなく、プロンプトの System / User 境界の厳密化、または文末語尾が「〜ですね」「〜ましょう」等の対話調に傾いた候補に対する SMC 対数尤度ペナルティ（文体一貫性スコープ判定）の導入。

### 課題B: 運動量放出と文体・破調方向の厳密なアライメント
- **現象**:
  - 制約あり（蓄電・放出大）で本文は分岐するものの、文長分散（$CV_L$）や Shock 平均の増減方向が一方向に揃っていない（seed 42 は制約ありで $CV_L$ 上昇、seed 3 は制約なしの方が $CV_L$ 高い）。
- **根本原因**:
  - 運動量 $\mathbf{p}$ は 12 次元シンプレクティックベクトル（Flux, Lattice, Void, Shock）であるにもかかわらず、現在の提案分布注入がスカラー量 $\|\mathbf{p}_{\text{discharge}}\|$ のみに潰されている。
- **解決方針**:
  - 単なるスカラーノルムではなく、Group IV（Shock）の成分が支配的な場合は短文・体言止め・破調バイアス、Group I（Flux）が支配的な場合は複文・接続詞バイアスといった、**方向性を持ったロジットステアリング** への拡張。

### 課題C: モデルスケールアップ（Qwen2.5-3B / 7B への移行）
- **背景**:
  - 1.5B モデル特有の語彙の貧困さ・アライメントの脆弱性（アシスタント口調の漏れ、文脈維持限界）がボトルネックになり始めている。
  - Colab L4（24GB VRAM）の環境であれば、Qwen2.5-3B または 7B（fp16 / bf16）が余裕をもって稼働可能。
