# Phase 42: 事前登録（末尾の断片を除いた報酬での GRPO、ロールアウトの保存つき）

## 目的
- Phase 36 の GRPO（シェイピング報酬）では、40 ステップで報酬が上がらなかった（0.286 → 0.281）。
- Phase 37 では、次の仮説を立てたが、ロールアウトを保存していなかったため検証できなかった。
  - 報酬が、256 トークンで切れた末尾の断片と、cadence_alive の段差（2 値）に左右されていた。
- 報酬を完全な文だけで計算し（`--reward-strip-tail`）、ロールアウトを保存して（`--store-rollouts`）、もう一度学習する。

## 実行
- ジョブ: `p42g_q3_8b`。
  - Qwen3-8B、A100、ステアなし（`--no-steer`）、seed 20261106。
  - 説明文のプロンプト（Phase 33・36 と同じ評価 12 本・学習 12 本）。
- GRPO の設定は Phase 36 と同じ。シェイピング報酬、40 ステップ、ロールアウト 256 トークン、LoRA r・α、学習率。
- 評価は max_new_tokens 1024。Phase 36 の評価は 400 トークンだった。

## 成功基準（すべて満たしたとき「末尾除去の報酬で GRPO が Deadzone を減らす」とする）
1. 学習の最後の 10 ステップの平均報酬が、最初の 10 ステップより 0.02 以上高い。
2. merged LoRA の Deadzone（末尾除去テキストの QDA）が base より少ない（各 n = 12）。
3. merged LoRA の退化（bigram < 0.5）が 0 件で、ref PPL の平均が base + 0.5 以内。

## 報告のみ（保存したロールアウトで、仮説を確かめる）
- 文の途中で終わるロールアウトの割合。
- 報酬と CV_L の相関、報酬と cadence_alive の相関。
- cadence_alive の分布（2 値かどうか）。
- 同じロールアウトを末尾除去なしで採点した報酬との差（Phase 36 の報酬との比較）。
- 1 系列、n = 12 なので、有意性は主張しない。

## 追記（実行前、レビュー役サブエージェントの指摘を受けて）
- 判定スクリプト `scripts/phase42_grpo_eval.py` を実行前に固定した。Phase 36 のデータを入れて動作を確認し、Phase 37 の値（末尾除去後の Deadzone: base 7、merged LoRA 8）が再現された。
- 報告項目に次を追加する（判定には使わない）。
  - 句点のないロールアウトの割合。
  - 最後の文末の位置。
  - これらの学習前半と後半での変化。
  - 目的: 報酬は末尾の断片を採点しないが、PPL バリアは全文で計算する。このため、文を終えずに採点の外へ逃げる学習が起き得るので、それを確かめる。
- 解釈上の注意:
  - 基準 2 は n=12 で、差 1 件でも満たす。偶然に満たす可能性があるので、基準 1 と合わせて読む。
  - cadence_alive の段差は末尾を除いても残る。この実行で確かめられるのは、末尾の断片についての仮説だけ。
