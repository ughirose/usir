### 指標の定義

- 型付き facts の集合を 4 水準でハッシュ化: **T3**=(subject, predicate, object)（人物 id はそのまま、その他は §2 の norm_text で正規化。指示の主指標）、**T2**=(subject, predicate, object が roster id ならその id／そうでなければ "VAL")、**T1**=(subject, predicate)、**T0**=predicate のみ。
- ペア一致率は、同一場面の 5 回から作る 10 ペアの一致割合（20 場面平均）。Jaccard も同ペアで平均。
- prior_state ハッシュは既存の `keys.prior_state_hash`。location だけを差し替えて再計算（**再計算値**。present・pov は同 run の実測値）。

## 3. 判定への接続

1. **型付き facts**: 不一致率は T3 で 1.00、最も粗い T0 でも 0.88 で、閾値 0.5 を大きく超える。「型付き facts を鍵に含める」設計は、この計測定義では成立しない。facts は鍵に入れず、「前提変化ありの表示＋裏で再検証」の緩い方式に倒す根拠になる。語彙の被覆は問題でなく（other 1.0%）、不一致の原因は語彙設計ではなく、注釈者が挙げる事実の件数・内容そのものの揺れ。
2. **location**: 閉じた語彙で 0.90 と閾値 0.9 に到達した。ただし、(a) 候補リストが計測対象の観測値由来で楽観的、(b) 作品別では 0.85〜1.00、transition 全体 0.892 で 0.9 未満、(c) 候補が少ない会話劇 001875 では prior ハッシュがかえって下がる。「location を正規化 ID として鍵に残せる」とは言い切れず、条件付き（作品ごとに事前に確定した場所リストがあり、場所なしを許す場合）に限る。
3. **other の割合**: 述語は 1.0%、location は 0%。語彙設計そのものの限界を示す水準ではないが、location は未知の場面での被覆が未検証。

## 4. Step 1 設計への提言（計測から言える範囲）

- facts（自由文・型付きとも）は鍵に含めない。prior として渡す facts の変化は、鍵ではなく「前提変化あり」の表示と、バックグラウンド再検証で扱う（Step 0 B の prior 感度の弱さとも整合する。ただし Step 0 の結論は n=3 で弱い）。
- prior_state の鍵は present + pov を中核にする。この 2 つだけなら一致 0.915。location を足すと、閉じた語彙で 0.835、自由文で 0.64〜0.74 に下がる。location を鍵に入れる場合は、作品ごとの場所リストを注釈前に確定し、`none` と未知（`other`）の扱いを決める必要がある。
- location の ID 化は有効だが（自由文 0.72→0.90、prior ハッシュ 0.74→0.835）、候補リスト作りの手間と、場所なしの場面の扱いが論点になる。
- 型付き facts の追加出力は約 2.5 秒の追加で受理率 100%（初回 ACCEPT）だった。診断用の補助情報として使う価値は残るが、鍵には使えない。

## 5. 残った問題・限界

- 注釈者は Sonnet 系サブエージェントで、正確なモデル ID は未確認。計測は 1 回あたり 20 場面×5 回、4 作品（複数視点の作品なし）。
- 候補リストは計測対象の観測値由来（楽観的）。未知の場面での閉じた語彙の被覆は未測定。
- 型付き facts は、1 つの述語設計・1 つの注釈者設定の結果。述語設計の変更、object の語彙固定（感情語・物の名前の正規化）、件数の制御（上限・必須項目）で一致率が変わる可能性はあるが未測定。
- prior_state ハッシュの閉じた語彙値は「実測した部品からの再計算」であり、パイプライン全体を閉じた語彙で動かした実測ではない。
- 遵守状況: 順序（strong → m05in）はサブエージェントの自己申告。M5-4 担当の 1 エージェントは、pack の先頭 13 行を読まずに offset 指定で読み、m05in を全体読みせず一部を Read/Grep で読んだと申告している（影響: 該当 pack の注釈が語彙リストの一部を見ていない可能性。3 pack）。check 前に自分で strong を修正したケース（q08eab9cd）、m05 の余分なキーを削除したケース（qd44b19ac）もあり、reject 件数 0 は「check 前の自己修正を除いた値」。
- ログの不具合: 並行書き込みで attempts.jsonl に空行が 1 行入り、qc783a89a の試行記録が 1 件消えたため、解析前に check を再実行して記録を補った（ACCEPT）。timing.jsonl・attempts.jsonl の空行は除去した。
- 所要時間はレート制限による中断を含む 3 件を除外。コスト未計測。
