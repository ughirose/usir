## 1. タスク1（Orion 確認事項1）: H1 / H2 非再現の 2×2 クロスラン切り分けとコード差分特定

### 1.1 コードレベルの定義差監査（行番号つき特定）

#### (a) 重心 $z^*_{corpus}$ および $z^*_{author}$ の計算母集団と幾何学的引数の致命的相違
- **Stage B-7** (`experiments/usir_v5_residual_specificity_level3.py` L201-248, L415-417):
  - コーパス重心 $z^*_{corpus}$ は青空文庫 106 作品（全サンプリング場面）の平均。
  - 作家重心 $z^*_{author}$ は該当作家の全作品（サンプリング場面）の平均。
  - ベクトル定義:
    $$v_{corp} = z^*_{corpus} - z_{before}, \quad v_{target} = z^*_{author} - z_{before}$$
  - 推敲前テキスト $z_{before}$ を基準点として、「コーパス重心へ向かう普遍的改善方向」$u_{corp}$ と「目標作家重心へ向かう方向」$v_{target}$ のなす角 $\theta$ を計算していた（B-7 の $\theta$ 中央値: 16.70°）。
- **Stage B-8** (`experiments/scale_separated_level3.py` L141-172, L363-364):
  - 重心 `corp_vec` は 40 作品のプロトタイプ平均（L334）。
  - **重大な実装バグ**: L363-364 において、
    ```python
    v_t = z_a - z_b  # 推敲微小差分ベクトルそのもの
    v_perp, rho, th, u_s, q = gram_schmidt_residual(v_t, corp_vec)
    ```
    なんと $v_{target}$ の引数に「推敲微小差分 $z_a - z_b$」を渡し、$u_{corp}$ の引数に「原点からの絶対座標ベクトル `corp_vec`」を渡していた。
  - そのため、$\theta$ は「推敲微小変化方向」と「特徴空間原点からコーパス重心への絶対位置ベクトル」の内積角を測る無意味な量となり、77.02° や 130.20° という直交・鈍角に歪んでいた。

#### (b) Class B（マクロ22件）の目標方向ベクトルの消失
- **Stage B-7** (L788-803):
  - D10 多訳ペアにおいて、目標重心 $z^*_{target}$ は Leave-One-Source-Out による「変換先トランスレータースタイル（TR_RIGID, TR_EMOTIONAL, TR_CONVERSATIONAL）」の平均ベクトルとして定義され、推敲差分がそのスタイル重心を指向しているかを評価していた。
- **Stage B-8** (L463-508):
  - 目標スタイル重心の計算が**完全に脱落**。
  - L496 で `aid = p["author_id"]` を参照しているが、Class B のデータセット中では `author_id` はすべて `'D10_TRANSLATOR'` となっていた。
  - 青空文庫の作家辞書 `proto_map` に `'D10_TRANSLATOR'` は存在しないため、`other_aids` は青空文庫全 10 作家となり、`other_proto_mean` は `corp_vec` と完全に一致した。
  - その結果、$v_{other} = other\_proto\_mean - corp\_vec = 0$ となり、D10 の全 16 ペアで $v_{other}$ が厳密にゼロベクトルとなった。

#### (c) なぜ Class B の vs 他スタイル で $W=5.0, p=0.6250$（有効 $N=5$）になったのか？
- **直接の原因**:
  - 上述の通り、D10 の 16 ペアはすべて $v_{other} = 0$ となり、`norm_vo < 1e-12` のガードにより `cos_others` に厳密に `0.0` が append されていた（L504）。
  - Class B 全 22 ペアのうち、非ゼロの `cos_others` を持っていたのは、文学作品改稿（ペア 16〜21）のわずか 6 件のみであった。
  - しかもそのうち 1 件が同一値であったため、Wilcoxon の非ゼロ差分数 `nonzero` は**ちょうど 5 件**（$N=5$）であった。
  - $N=5$ の Wilcoxon 符号付き順位和検定において、片側の順位和が 5 となる確率は組合せ上 $p = 0.6250$ であり、$W=5.0, p=0.6250$ は計算破綻による必然的結果であった。
- **D10 ペア構成変化**:
  - B-7 では「TR_STANDARD → 3スタイル」の 12 方向ペアであったのに対し、B-8 では逆変換（3スタイル → TR_STANDARD）および TR_RIGID → TR_EMOTIONAL の 16 ペアが混入していた。

#### (d) 特徴量の事前標準化と Wilcoxon 検定の片側/両側設定
- **Stage B-7**:
  - 実測コサインとランダム/他作家コサインの差差分 $(c_{spec} - c_{rand})$ に対し、`alternative='greater'`（片側検定）を実施。
- **Stage B-8**:
  - 差差分ではなく、乱数内積 `cos_rands` そのもの、および `cos_others` そのものを 0 と比較する `alternative='two-sided'`（両側検定）を実施していた。

| **関数名** | `closed_class_coverage_ratio` / `closed_class_breakdown` | `evaluate_cross_entropy` (第2返り値) | 同名だが物理量が異なる |
| **分子** | `closed_known` (訓練コーパス既知の閉記号数) | `closed_hits` (評価文中の閉記号数) | **分子の定義違い** |
| **分母** | `closed_tokens` (評価文中の閉記号総数) | `len(tokens)` (評価文中の全骨格記号数) | **分母の定義違い** |

| **物理的意味** | **学習時閉クラス語彙に対する既知語被覆率** (Vocab Coverage) | **文中の閉クラス機能語密度** (Token Density) | Rust の `closed_share` に相当 |
