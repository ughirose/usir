# Colab 高速化と CU 消費の報告（2026-11-07）

## 1. 何を変えたか
| 項目 | 変更前 | 変更後 | コミット |
|---|---|---|---|
| GPU | A100（標準） | L4（標準）。A100 はユーザー許可時のみ（`--allow-a100`） | `0689e7e` |
| 評価生成 | 1 プロンプトずつ（バッチ 1） | 12〜24 行をまとめて生成（`--gen-batch`） | `0689e7e`, `cccb10c` |
| ステアリング条件 | 条件ごとに別の generate | 条件をまたいで同じバッチ（行ごとの注入ベクトル、`--mixed-steer`） | `1bbea99` |
| 遅延測定段 | 毎回実行（約 44 s） | `--latency-reps 0` で省略（フック負荷は ±1% 以内と測定済み） | `9aa9620` |
| 系列 | 1 系列 = 1 ジョブ（毎回モデル読み込み） | 複数 seed を 1 ジョブで実行（`--seeds`、読み込み 1 回） | `5ce2938` |
| 解放確認・CU | 確認手段なし | `scripts/colab_assignments.py` で割り当て数と CU 残高を表示。ジョブごとに `<名前>.ccu.json` へ使用 CU を記録 | `0689e7e`, `5ce2938` |

## 2. 同じ作業量での実測比較（Phase 40 の全量: 4 系列 × 5 条件 × 12 プロンプト = 240 本、上限 1024 トークン）
| | 変更前（Phase 40） | 変更後（p46） |
|---|---|---|
| GPU | A100 | L4 |
| ジョブ数 | 4 | 1 |
| 実行時間 | 6593 s（1623 + 1676 + 1675 + 1619、割り当て失敗の試行は含まない） | 926 s（割り当てから解放まで） |
| 使用 CU | 未記録（下の推定を参照） | **0.48 CU**（実測。残高 228.73 → 228.24） |
| 消費レート | 未計測 | 1.94 CU/h（実行中の ccu-info） |
| 出力 | 240 本、エラー 0、上限到達 0 | 240 本、エラー 0、上限到達 0。合計 142,693 字、平均約 420 トークン |

- 実行時間は 7.1 倍短くなった。
- 変更前の CU は記録がないため、A100 の公開測定値から推定した。

| A100 のレート（仮定） | Phase 40 の推定 CU | 変更後との比 |
|---|---|---|
| 5.40 CU/h（McCormick, 2026-03 の測定） | 9.9 | 約 21 倍 |
| 10.59 CU/h（2024 年の比較記事） | 19.4 | 約 40 倍 |

- 上の推定には、割り当てに失敗した試行と、解放されずに残ったランタイムの時間が入っていない。
  - 解放されなかった A100 は、少なくとも Phase 40 の s2・s4 と Phase 42 の 3 件。
  - それぞれの残存時間は記録がない。1 件が 1 時間残ると、それだけで 5〜11 CU になる。
- A100 の実レートは、許可なしに割り当てられないため測っていない。

## 3. 今後の生成可能量（現在の残高 228.24 CU、2026-11-07 実測）
- 単価（実測から算出）
  - 1 系列（60 本）あたり 0.12 CU。
  - 1 本（約 600 字）あたり 0.0020 CU。
  - 1 万字あたり 0.034 CU。
- 残高で回せる量（同じ形のステアリング評価ジョブを続けた場合）

| | 変更前の方式（A100 バッチ 1、5.40 CU/h 仮定） | 変更後（L4、実測） |
|---|---|---|
| 系列数 | 約 92 系列 | 約 1,900 系列 |
| 本数 | 約 5,500 本 | 約 114,000 本 |
| 字数 | 約 330 万字 | 約 6,800 万字 |
| L4 の稼働時間 | – | 約 118 時間 |

- 限界と未検証の点
  - GRPO（LoRA 学習）は `--seeds` に対応していない（学習でモデルが変わるため）。L4 での時間と CU は 2026-11-08 に実測した（第 4 節）。
  - バッチ化すると、同じ seed でもバッチ 1 とは別のサンプルになる。過去の Phase の値との直接比較はしない。新しい Phase は、この方式で事前登録する。
  - CU レートは Colab 側で変わりうる。毎ジョブの `.ccu.json` で実測を追う。

## 4. GRPO を L4 で実測（Phase 47, 2026-11-08, `docs/handoff/v10/p47g_q3_8b.*`）

- 設定は Phase 42（`p42g_q3_8b`）と同じ: shaped 報酬・完結文のみ、40 ステップ、2 プロンプト/ステップ × 4 ロールアウト、ロールアウト 256 トークン、評価 12 本 × 上限 1024 トークン。違いは評価生成を `--gen-batch 24` でまとめた点だけ（GRPO 学習部分は同一コード・同一設定）。

| | Phase 42（A100） | Phase 47（L4） |
|---|---|---|
| ジョブ全体（kernel 内） | 2,290 s | 2,145 s |
| ランナー全体（割当〜解放） | 記録は 2,460 s | 2,267 s |
| GRPO 学習 | 1,515 s（37.9 s/step） | 1,762 s（44.0 s/step） |
| 学習ピークメモリ | 18.7 GB | 18.7 GB（L4 で収まった） |
| エラー / 上限到達 | 0 / 0 | 0 / 0（base・lora_merged とも 12/12） |
| 使用 CU | 記録なし（推定 3.4〜6.7） | **1.13**（実測、228.24 → 227.11、1.94 CU/h） |

- 学習 1 ステップは L4 で A100 の 1.16 倍の時間に留まった。ジョブ全体は評価のバッチ化で L4 の方が短い。
- A100 側の CU は、2,290 s に公開レート 5.40 / 10.59 CU/h を掛けた推定。実測ではない。
- 終了後の割り当ては 0 件、消費 0 CU/h（`colab_assignments.py` で確認）。
- 残高 227.11 CU で、この GRPO ジョブは約 200 回分。
- 学習結果: 最終平均報酬 0.2655、mean KL 0.0104、PPL 閾値 1.702（Phase 42 は 1.736）。評価サンプルはバッチ化で Phase 42 と別物なので、品質指標の直接比較はしない。
- 未実施の高速化候補（学習の数式は変えない）: 参照モデルの forward が同じ入力で 2 回行われている（`lora_grpo_forge.py:513` の PPL 用と `:566` の KL 用）。共有すれば 1 ステップの forward を 8 回減らせる。ただし片方だけ attention_mask を渡しており、数値一致は未検証。ステップ内の decode と forward/backward の時間内訳も未計測。
