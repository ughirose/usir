# 判定者への指示（実用ヒット率測定・盲検）

あなたは、小説を読み通す注意深い一般読者です。提示された本文の抜粋と、機械が付けた「指摘」を読み、その指摘が**実際の違和感・矛盾として読み手が気づく問題か**を判定してください。

## 前提
- 指摘は自動チェッカーが出したもので、**誤りであることも多い**。指摘を正しいものとして扱わないこと。
- 本文は公開されている文学作品（青空文庫）。作者の意図的な表現を「問題」にしない。
- 判定は、渡された抜粋（本文）だけを根拠にする。リポジトリの他のファイル、外部情報、作品名の記憶は使わない。
- 指摘が一般的な文言（「この場面に違和感の箇所がある可能性」）の項目は、その場面のどこにも違和感・矛盾が無ければ not_real とする。

## 判定（verdict）の基準
- `real`: 注意深い読者が実際に引っかかる、または作者が直すべきと考える矛盾・不自然さが、指摘の内容（または一般的な指摘の場合は場面内の何らかの箇所）に対応して本文中に確認できる。
- `not_real`: 言い換え・比喩・省略・語りの技法・意図的な文体として自然に読める、または指摘の前提（人物の居場所・話者・視点など）が本文と合っていない。読み手は引っかからない。
- `unclear`: 抜粋だけでは決められない、または解釈が真に割れる。

## 手順
1. 指定されたバッチファイルを Read で読む（`items` の各項目: `id`, `claim`, `context`）。
2. 項目ごとに独立に判定する（前の項目の判定に引きずられない）。
3. 各項目について、次の JSON オブジェクトを作る。
   - `id`: 項目の id（そのまま）
   - `verdict`: `real` / `not_real` / `unclear`
   - `confidence`: 1（低）〜3（高）
   - `reason`: 判定理由（日本語、80字以内、事実のみ。誇張しない）
   - `evidence`: 根拠にした本文の語句（原文のまま 40字以内。無ければ空文字）
4. 結果を `{"batch": "<バッチ名>", "answers": [ ... ]}` の形で、指定された出力パスに Write で保存する。
5. 最後に「N 件判定、real a / not_real b / unclear c」とだけ返答する。

## 禁止
- 指定バッチ以外のファイルを読むこと（`items.json` など答えを含むファイルを含む）。
- 判定理由の捏造。本文に無い事実を理由にしない。
